What the solution delivers

  • One explicitly selected Azure subscription; local or one Container App.
  • Eight typed, read-only tools for costs, breakdowns, Advisor, opportunities, health, evidence, reports and guidance.
  • Five checked answer sections: Answer, Evidence, Data health, Risks, Next action.
  • PDF, XLSX, CSV, JSON, HTML and FOCUS outputs from the same report revision.
  • Only done.validated=true marks a successful model-backed answer.

Snapshot behavior

  • Charts, tables and reports make zero provider or model collection calls.
  • Hosted state is normalized Blob content plus a Cosmos revision pointer.
  • The model receives minimized evidence, never credentials or raw billing rows.

Financial truth and safety

  • Preserve billed/effective basis, currency, dates, exclusions and collection time.
  • Missing or incomplete evidence stays unknown, never zero.
  • Advisor savings are estimates and may overlap; they are not targets or realized savings.
  • Never paste passwords, keys, tokens or private identifiers into chat or screenshots.
  • Pass the subscription explicitly; never change the global Azure CLI default.
  • Use supplied Bicep in Incremental mode and deploy only an immutable image digest.

Mandatory approval stops

Stop before every Azure read or write, role assignment, model deployment, paid inference, public-access change, deployment or deletion. A successful what-if is evidence, not approval.

Sprint 1 | Connect locally

  1. Prepare: check tools; install nothing without approval.
  2. Sample: prove OFFLINE SAMPLE with zero Azure/model calls.
  3. Context: sign in privately and select subscription/tenant.
  4. Inputs: record region, names, owner, expiry and required tags.
  5. Access: review the bounded read-only check, then approve or defer.
  6. Live-local: start cost-only; one approved refresh, never at startup.
  7. Parity: compare identical scope, dates, ActualCost, billed basis, currency and time.
  8. Agent ACO: separately approve model connection and one inference, or record activation false/deferred.

Sprint 2 | Deploy and validate

  1. Resume: confirm scope, model, spend, owner, expiry and access.
  2. Foundation: review what-if; approve Apply separately.
  3. Model: reuse or deploy only after capacity, quota, cost and access review.
  4. Image: use ACR remote build; record repository@sha256:....
  5. App: review application what-if, then deploy the supplied workflow.
  6. Smoke: verify health, access, evidence, views, Advisor, reports and responsive fit.
  7. Experience: approve one full review, generate PDF/XLSX and review a screenshot.
Recovery rule: record 403, 429, policy, model, quota or propagation blockers precisely. Never hide a live blocker with sample data, self-grant access, spin retries or weaken security to finish the workshop.
